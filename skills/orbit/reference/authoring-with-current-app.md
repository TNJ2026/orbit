# Authoring With The Current App

Use the stable client name `codex-app`. It is displayed as `codex-app` in
Orbit. The distinct address is intentional: a Runtime commonly discovers the
Codex CLI as the authoring Agent `codex`, and client names may not shadow
installed Agents.

## Request starts in Codex chat

When the user asks this task to generate a new workflow:

1. Call `register_authoring_client` with `client="codex-app"`.
2. Call `generate_workflow` with the user's prompt, `agent="codex-app"`, the
   user's display language, and a fresh idempotency key.
3. Poll `claim_authoring_request` with `client="codex-app"` until its `request`
   contains the generation prompt for that job.
4. Tell the user which authoring stage is running, follow the returned prompt
   exactly, and produce one Workflow DSL JSON document. Do not wrap it in
   Markdown.
5. Call `submit_authoring_response` with the returned `request_id` and DSL.
6. Call `get_authoring_job`. If compilation requests another attempt, repeat
   the claim, generation, and submission steps. Stop when the job is done,
   failed, cancelled, or the user stops it.
7. On success, report the published workflow name and identifier. A workflow
   list already visible in Orbit should be refreshed before claiming it is
   up to date.

Narrate useful milestones in the Codex conversation, but never paste hidden
reasoning. The authoring job's console and compiler diagnostics are the source
of truth for progress and failure.

## Request starts in the Orbit UI

When the user wants a workflow generated by this task after clicking Generate
in Orbit:

1. Call `wait_authoring_request` with `client` set to `codex-app` and
   `timeout_seconds` set to 300.
2. Tell the user to select `codex-app` in Orbit and click Generate while the
   tool call is waiting.
3. When the tool returns a request, follow its prompt exactly and produce one
   Workflow DSL JSON document. Do not wrap the document in Markdown.
4. While generating, watch the App event stream for `request_cancelled` with
   the same `request_id`. If received, abort the model request when the App
   supports cancellation, discard partial output, and do not submit it.
5. Call `submit_authoring_response` with the returned `request_id` and the DSL
   object.
6. Call `get_authoring_job` with the returned `job_id`. If compilation requests
   another attempt, wait again with the same client name and submit the revised
   document. Stop when the job is done, failed, cancelled, or the user stops it.

The wait call is what makes `codex-app` visible in Orbit. A timeout means no
request arrived; it is not a generation failure and may be started again.
Orbit rejects a response submitted after cancellation even when the App cannot
interrupt its underlying model request.
